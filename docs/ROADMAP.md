# Markdown Leo Roadmap

## Product Strategy Summary

Markdown Leo should evolve in three steps:

1. Become reliable for daily writing
2. Become efficient for multi-document local projects
3. Become differentiated through advanced editing and workflow features

## V1.0 - Daily Usable

### Goal

Make the app stable and trustworthy enough for regular Markdown writing.

### Focus Areas

- Fix Chinese copy and encoding issues
- Polish open, save, save as, and auto-save flows
- Improve unsaved-change protection
- Expand Markdown rendering support
- Improve exported HTML quality
- Add a basic settings surface

### Key Features

- Correct localized copy
- Clear status messages
- Better failure and empty-state feedback
- Common Markdown support improvements
- Basic export styling
- Theme, language, and auto-save preferences

### Success Standard

Users should be able to write and maintain a single document confidently without worrying about losing content.

## V1.5 - Frequent Use

### Goal

Support small local documentation projects with better navigation and organization.

### Focus Areas

- Search
- Navigation
- Workspace productivity
- Multi-document workflow

### Key Features

- Global search by file name and content
- Multi-tab editing
- Document outline
- Preview scroll sync
- Recent folders and pinned folders
- Local image insertion and asset management

### Success Standard

Users should be able to manage a local project containing 20 to 100 Markdown files efficiently.

## V2.0 - Differentiation

### Goal

Create clear product reasons to choose Markdown Leo over a basic editor.

### Focus Areas

- Advanced writing workflows
- Structural editing
- Extensibility
- Optional intelligence features

### Key Features

- Dual editing modes or rich-text integration
- Document templates
- Cross-document references
- Plugin system
- AI-assisted writing or formatting helpers

### Success Standard

Users should feel that Markdown Leo is a writing workspace rather than only a Markdown editor.
